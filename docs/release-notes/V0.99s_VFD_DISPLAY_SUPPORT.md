# CryptoBar V0.99s - VFD Display Support (Retro Edition)

**Release Date:** 2026-01-19

## Overview

V0.99s introduces **VFD (Vacuum Fluorescent Display) support**, enabling CryptoBar to run on retro 16-character single-line displays using the PT6302 controller. This release adds a complete parallel display driver architecture while maintaining **100% backward compatibility** with e-ink displays.

**Key Features:**
- 🎯 **Dual Display Support**: Automatic detection of e-ink or VFD displays
- 📺 **Retro VFD Display**: 16-character IGL VFD Studio with smooth animations
- 🔄 **NTP-Synced Updates**: Multi-device synchronization via 10-second cycles
- 🌙 **Auto Brightness**: Time-based brightness control with night mode
- ⚡ **Anti-Burn-In**: Automatic pixel aging protection at 04:00
- 🎨 **Horizontal Scrolling**: Smooth left-scroll page transitions
- ✅ **Zero E-ink Impact**: All e-ink functionality preserved unchanged

---

## 🎯 What's New

### 1. VFD Display Driver Architecture

#### Hardware Support
**Supported Display:**
- **IGL VFD Studio** 16-character dot matrix display
- **Controller**: PT6302 (Princeton Technology)
- **Dimensions**: 16 characters × 1 line
- **Resolution**: 5×7 pixels per character
- **Brightness**: 8-bit PWM control (0-255)
- **Interface**: 3-wire SPI (CLK, DIN, CS) + RST

**GPIO Configuration:**
```cpp
#define VFD_CLK  18  // SPI Clock
#define VFD_DIN  23  // SPI Data In
#define VFD_CS   5   // Chip Select
#define VFD_RST  17  // Reset
```

#### Automatic Display Detection
System automatically detects display type on boot:
```cpp
DisplayType detectDisplayType() {
  // Check for PT6302 VFD controller on I2C bus
  if (VFD detected) {
    return DISPLAY_VFD;
  } else {
    return DISPLAY_EINK;  // Default to e-ink
  }
}
```

**Boot Behavior:**
- **VFD Mode**: Shows "CryptoBar Retro" during initialization
- **E-ink Mode**: Shows standard splash screen with version

#### 2.2 NTP-Synced Multi-Device Synchronization

**Problem Solved:**
Previous implementations used `millis()` (relative time since boot), causing each device to display different content at different times.

**Solution:**
Uses absolute UTC timestamps for page rotation:
```cpp
void updatePageRotation() {
  time_t nowUtc = time(nullptr);
  uint8_t cycleSecond = nowUtc % 10;  // 0-9 position in 10-second cycle

  uint8_t targetPage = (cycleSecond < 5) ? 1 : 2;
  // Page 1: seconds 0-4
  // Page 2: seconds 5-9
}
```

**Benefits:**
- ✅ All devices display same content at same UTC second
- ✅ Perfect synchronization when NTP is accurate
- ✅ 6 complete cycles per minute (60s ÷ 10s)
- ✅ Predictable page transitions

**Transition Animation:**
- Horizontal left-scroll effect (500ms duration)
- Old content exits left, new content enters from right
- Two-phase animation for smooth 16-character display

#### 2.4 Night Mode & Anti-Burn-In Protection

**Night Mode (02:00-06:00):**
- Display brightness set to minimum (1/255)
- Content updates continue normally
- LED status still indicates price changes

**Anti-Burn-In Routine (04:00-04:04):**
Runs automatic pixel aging to prevent uneven phosphor wear:

```cpp
void runNightMode() {
  if (hour == 4 && minute < 4) {
    uint8_t pattern = minute;  // 0-3

    switch (pattern) {
      case 0:  // 04:00-04:01: All segments ON
        vfdCommand(0xE9);
        break;
      case 1:  // 04:01-04:02: All segments OFF
        vfdClear();
        break;
      case 2:  // 04:02-04:03: Checkerboard pattern
        displayCheckerboard();
        break;
      case 3:  // 04:03-04:04: All characters pattern
        displayAllCharacters();
        break;
    }
  }
}
```

**Why 04:00?**
- Statistically least active time for home users
- Middle of sleep period (02:00-06:00)
- Ensures daily maintenance without user disruption

#### 2.5 Temporary Brightness Boost

**Problem:**
Users want to check prices at night without keeping display bright 24/7.

**Solution:**
Rotating encoder during night hours temporarily boosts brightness for 5 minutes:

| Time Period | Normal Brightness | Boost Brightness | Boost Duration |
|-------------|-------------------|------------------|----------------|
| 22:00-02:00 | 30% (Night) | 50% (Evening) | 5 minutes |
| 02:00-06:00 | Minimum (Sleep) | 30% (Night) | 5 minutes |

**Implementation:**
```cpp
void handleEncoderActivity() {
  if (hour >= 22 || hour < 2) {
    // Night time: boost to 50%
    tempBrightBoostEndTime = millis() + 5 * 60 * 1000;
    vfdSetBrightness(128);
  } else if (hour >= 2 && hour < 6) {
    // Sleep time: boost to 30%
    tempBrightBoostEndTime = millis() + 5 * 60 * 1000;
    vfdSetBrightness(64);
  }
}
```

**User Experience:**
1. User rotates encoder at 23:00
2. Display brightness increases from 25% → 50%
3. User navigates menu or adjusts settings
4. After 5 minutes of inactivity → brightness returns to 25%

**Note:** Only applies in Auto brightness mode.

### 6. Pixel-Level Scrolling Animation

#### 6.1 Horizontal Left-Scroll Implementation

**Animation Strategy:**
- Old content exits left, new content enters from right
- Smooth character-level horizontal scrolling
- 500ms animation duration (configurable)
- Uses CGRAM (Character Generator RAM) for custom characters

**Technical Details:**

**Phase 1: Left Half (Characters 0-7)**
```cpp
for (uint8_t frame = 0; frame < 8; frame++) {
  // Mix old and new character pixels based on frame offset
  // CGRAM slots 0-7: animated characters
  // Right half: smooth ASCII transition
}
```

**Phase 2: Right Half (Characters 8-15)**
```cpp
for (uint8_t frame = 0; frame < 8; frame++) {
  // Left half: show final new text
  // CGRAM slots 0-7: animated characters (right half)
}
```

**Why Two Phases?**
- PT6302 has only 8 CGRAM slots
- Animating all 16 characters requires two passes
- Prevents visual artifacts and glitches
- 5ms stabilization delay between CGRAM writes

**Pixel Mixing Algorithm:**
```cpp
void mixCharPixels(uint8_t* output, const uint8_t* oldChar,
                   const uint8_t* newChar, uint8_t offset) {
  // offset: 0-7 (0=old visible, 7=new visible)
  // Each column: blend old pixels (top) with new pixels (bottom)
  for (uint8_t col = 0; col < 5; col++) {
    uint8_t oldPart = oldPixels >> offset;
    uint8_t newPart = (newPixels & mask) << (7 - offset);
    output[col] = oldPart | newPart;
  }
}
```

### 9. Technical Specifications

#### 9.1 VFD Hardware Requirements

**Minimum Requirements:**
- **ESP32 DevKit** (any variant with ≥4MB flash)
- **IGL VFD Studio Display** (16-character PT6302)
- **4 GPIO pins**: CLK, DIN, CS, RST
- **5V power supply** (VFD requires ~500mA peak)

**Recommended Setup:**
- ESP32-WROOM-32 DevKit V1
- External 5V/1A power supply (not USB)
- Level shifter if using 5V VFD logic (ESP32 is 3.3V)

#### 9.2 Performance Metrics

**VFD Display:**
- **Initialization**: ~2 seconds
- **Page rotation**: 10-second cycle (NTP-synced)
- **Scroll animation**: 500ms (configurable)
- **Brightness update**: Instant (PWM)
- **Menu navigation**: <100ms response

**Memory Usage (vs V0.99r):**
```
Flash:   +45KB (display_vfd.cpp, interface code)
RAM:     +2KB (VFD state, CGRAM buffers)
Heap:    +1KB (DisplayVfd object)
Total:   ~48KB additional
```

**E-ink Impact:**
```
Flash:   +0KB (conditional code paths)
RAM:     +64 bytes (1 settings field)
Performance: No measurable change
```

#### 9.3 Power Consumption

**VFD Mode (Typical):**
- **Daytime (85% brightness)**: ~350mA @ 5V
- **Night (25% brightness)**: ~150mA @ 5V
- **Sleep (minimum)**: ~50mA @ 5V
- **Auto mode average**: ~200mA @ 5V

**E-ink Mode (Unchanged):**
- **Idle**: ~80mA @ 5V
- **Refresh**: ~200mA peak @ 5V
- **WiFi active**: +100mA @ 5V

### 11. Troubleshooting

#### 11.1 VFD Detection Issues

**Symptom:** Device boots in e-ink mode despite VFD connected

**Possible Causes:**
1. VFD not powered (requires 5V)
2. GPIO pin conflict
3. PT6302 not responding on I2C bus

**Solution:**
```cpp
// Check serial output on boot:
[Display] Detecting display type...
[Display] VFD PT6302 detected - CryptoBar Retro mode  // ← Should see this
```

**Manual Override (if needed):**
```cpp
// In main.cpp, force VFD mode:
g_displayType = DISPLAY_VFD;
g_display = new DisplayVfd();
g_display->init();
```

---

#### 11.2 VFD Display Issues

**Problem: Blank Display**
- Check power supply (VFD needs 5V, not 3.3V)
- Verify GPIO connections (CLK, DIN, CS, RST)
- Check serial log for initialization errors

**Problem: Garbled Characters**
- CGRAM stabilization delay too short
- Increase delay in `scrollLeftCharLevel()`:
  ```cpp
  delay(2);  // Try increasing to 5ms
  ```

**Problem: No Scroll Animation**
- Animation happens at cycle position 4-5 and 9-0
- Wait up to 10 seconds to see transition
- Check NTP time sync status

**Problem: Brightness Not Changing**
- Verify Auto mode is selected (not fixed brightness)
- Check system time is valid (NTP synced)
- Serial log shows: `[VFD] Brightness: X/255 (hour=Y)`

---

#### 11.3 Menu Navigation Issues

**Problem: Timezone Submenu Displays Truncated Text**
- **Fixed in V0.99s commit fe199d5**
- Update to latest version
- Timezone now shows full name (e.g., "UTC-02 S.Georgia")

**Problem: Can't Enter Submenu**
- Ensure short press (not long press)
- Long press exits menu
- Check serial log for UI mode changes

**Problem: Settings Not Saving**
- VFD brightness saved to `vfdBriPreset` field
- E-ink settings saved to existing fields
- NVS namespace: `cryptobar`
- Erase flash and reconfigure if corrupted

### 13. Known Limitations

#### 13.1 VFD Display Constraints
- **No time display**: 16 characters insufficient for time + price
- **No chart display**: Single-line display cannot show graph
- **Limited text**: Long strings truncated or require scrolling
- **No color**: Monochrome blue-green phosphor only

#### 13.2 Scrolling Animation
- **Current**: Simple truncation for most menu items
- **TODO**: Full auto-scroll implementation (stopped in code comments)
- **Workaround**: Keep all menu text ≤ 16 characters

#### 13.3 E-ink Features Not Available on VFD
- Refresh mode (Partial/Full) - not applicable
- Time/Date format settings - no time display
- DateTime size options - no time display
- Day average line - no chart display
